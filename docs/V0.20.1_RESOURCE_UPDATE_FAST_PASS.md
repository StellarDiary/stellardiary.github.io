# V0.20.1 — Resource Update Fast Pass

## Goal
Remove the brief “checking for updates” flash for players whose current build and page resources are already prepared, while preserving the blocking updater for first setup, real version upgrades, and pages that still need resources.

## Changes
- Each HTML entry performs a tiny synchronous preflight in `<head>` before page content is parsed.
- If `stellar-installed-version` matches the page build and the current route has a matching `stellar-prepared-group:*` marker, the page renders immediately with no updater overlay.
- The normal update UI is now opt-in: it becomes visible only when the synchronous preflight says preparation is required, or a background check discovers a real newer version.
- Ready pages perform a silent `version.json` check in the background. A matching version produces no UI.
- A session-scoped 5-minute check marker reduces repeated version requests while moving between pages in the same browsing session.
- Previously prepared route groups whose asset revisions did not change are promoted into the new version cache, so a small release does not force players to re-open every page through a preparation screen.
- A newly published build still blocks entry until required shell + route assets are fully prepared.
- First-time visits and routes that have never been prepared keep the V0.20.0 progress experience.
- Update failures still block only when an actual preparation/update is in progress; a failed silent check never interrupts an already-ready site.
- Service Worker, Cache Storage, incremental hash reuse, old-cache fallback, and on-demand large-asset caching remain unchanged.

## Deployment rule
Every public deployment that changes managed files must continue to increment the site version. Silent background checks use `version.json` as the authoritative signal that a new release exists.

## Database
No Supabase schema or migration changes are required.
